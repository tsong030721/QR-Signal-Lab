# V1 : Foundation for Practical Research System


## Objectives
- Engineer Features & Define Signals
- Build Strategy & Compute Returns
- Execute Backtesting & Evaluate Performance
Build a strong workflow and foundation for research mechanics.

V1 forces me to question "*Is it stable*" instead of "*Does it work?*".
- Split in-sample / out-of-sample (tuning/testing period)
- Compare multiple signals
- Test robustness (parameter sweeps: testing multiple values)


### Feature Layer
V1 computes:
- Rolling statistics (volatility, momentum, mean reversion)
- Cross-sectional features - comparisons across assets at same time (rank, z-score)
- Regime features - descriptors of market environment (trend filters, volatility filters)
- Basic technical signals (**optional**)
From **price data** to **feature matrix**.

### Strategy Layer
V1 implements a minimal strategy with:
- Signal-to-position mapping
- Position sizing  & holding period logic
- Transaction cost assumptions
- Basic PnL calculation
Even if it's brutally simple, you turn a **signal** into a **tradable decision**.

### Backtesting Layer
V1 implements a minimal backtester that:
- Computes daily returns & cumulative PnL
- Applies position
- Computes sharpe, drawdown, turnover, win Rate
Simple vectorized Pandas backtest.

## Navigation
What to sharpen and what to avoid.

### Research Landmines
Confront and avoid:
- Lookahead bias - accidental usage of future information
- Survivorship bias - neglecting assets that have died off
- Data leakage - training data contains info that would not be available at prediction
- Overfitting
- Curve fitting via parameter tweaking

### Numerical Intuition
When evaluating numbers, ask: "*Does this magnitude make sense?*"

### Engineering Discipline
Sharpen: **reproducibility**, **modular code**, **deterministic outputs**, **data manipulation**.

### Financial Perspective
Think in terms of returns, not price charts - **log/excess/risk-adjusted returns**.
